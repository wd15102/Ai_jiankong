# 历史查询与日报存档（2026-09-04 新增）

## 一、文本指令查监控（功能1）

在公众号对话框直接发指令，例如：

- **查询双溪村10点左右的监控**
- 查一下木山村昨天下午3点的报警
- 查询双溪村昨晚8点到10点的监控
- 查询双溪村10点30分的记录
- 查询双溪村的监控（无时间=查当天全天）
- 看看木山村监控录像

### 返回内容（不筛是否有人，直接返回该时段全部报警记录）

1. 秒回一条「正在查询…」提示
2. 客服消息发 **文字汇总**：每条记录的时间+设备+类型+AI分析结论一行（最多8条）
3. 客服消息发 **最多3张截图**（取离所查时段中心最近的3张）
4. 一张 **图文卡片**，点开进入 /history 完整页（当天全部记录+截图+AI结论）

### 时间解析规则

| 写法 | 查询范围 |
|---|---|
| 10点左右 | 09:00 ~ 11:00（±1小时） |
| 10点30分 | 10:00 ~ 11:00（±30分钟） |
| 8点到10点 | 08:00 ~ 10:00 |
| 下午3点 | 14:00 ~ 16:00（时段词自动补+12小时） |
| 凌晨/早上/上午/中午/下午/傍晚/晚上 | 对应时段整段 |
| 昨天 / 前天 | 自动按天回退 |
| 不写时间 | 当天全天 |

### 数据来源

- 本地 events.json 优先；查询时会**先向萤石云端按时间窗补录**（全类型告警，不筛人）
- 注意：**萤石云端告警只保留最近 7 天**（官方限制），更早的时段只能查本地已有记录
- 没有 AI 结论的记录会现场补判读（最多补 2 条，避免回复太慢）

### 权限

- 同事组（仅状态权限）不可用
- 双溪村分组成员只能查双溪村；不写村名时自动按所在分组过滤

## 二、历史记录按钮（功能2）

### 入口（三种）

1. 公众号菜单新增 **「历史记录」** 按钮（key=history），点开直接收到图文卡片
2. 对话框发送 **「历史」** 或 **「历史记录」**
3. 图文卡片 / 直接打开 https://<花生壳域名>/history

### 历史页功能

- **日期导航**：‹ › 前后翻天，下拉框快速跳到有记录的日子
- **三个标签**：👤 有人记录（默认）／📋 全部记录（含无人）／📊 日报（总数/分村/分设备+逐条时间线）
- 分组成员打开自动只显示本村数据（链接自动带村参数）

## 三、最多能查询多久的历史？（重点结论）

| 数据 | 保留时长 | 说明 |
|---|---|---|
| **报警记录+AI结论+截图** | **约90天** | 截图由 captureRetentionDays=90 控制自动清理；events.json 记录上限从 500 条（约3~5天就挤满）提升为 storage.eventRetention=20000 条（按目前每天约80~100条报警 约等于90天） |
| **历史日报** | **从 2026-09-04 起永久累积** | 每晚日报推送成功后自动存档到 data/daily_reports/日期.json；之前没有存档的日期，只要本地有监控记录会**自动重算**一份（所以目前 9/2 起每天都有可看的日报） |
| **萤石云端补录** | **最近 7 天** | 官方限制，超过7天的时段无法从云端补录，只能查本地已存过的记录 |

> 实际可查上限 = 上面三项的最小值。当前部署于 2026-09-01，从今天起理论上可回查到部署日，此后长期滚动保留 90 天。
> 想保留更久：调大 config.json 里 storage.captureRetentionDays（截图）与 storage.eventRetention（记录条数，按 每天约100条×天数 估算）。

## 五、技术细节（维护备查）

- webhook.js 新增：parseHistoryQuery / collectWindowEvents / sendHistoryQueryResult / buildHistoryEntryReply / saveDailyReportSnapshot / loadDailyReportSnapshot / buildReportForDate / HISTORY_PAGE_HTML + 路由 /history、/api/history-events、/api/history-days、/api/history-report
- 指令解析防误触：「看家」「门口」等原关键词不受影响（解析器要求 查询类动词+监控类名词，或「看看+监控+时间/村名」组合）；「直播」优先走直播分支
- 90 秒软去重：实时推送与云端补录的时间戳差异会造成同一次活动两条记录，查询结果里同设备 90 秒内合并为一条（优先保留有图有AI的）
- 每次查询最多从云端补下 10 张图，防止大窗口拖慢回复
- events.json 写入上限三处同步：webhook.js（读cfg）/ monitor.js / webapp.js（默认20000）
