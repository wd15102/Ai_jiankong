## 二、特征提炼

### ✅ 稳定特征（7 张中反复出现，可作为身份依据）

- **年龄体态**：高龄老年男性（体态上看约 80 岁上下），**身材偏瘦削、精干**，不臃肿、没有明显佝偻。
- **发型**：**灰白色短寸头**（所有露头照片一致）。
- **着装风格**：朴素的老式农家打扮——多为 **蓝色系长袖上衣 / 外套**（7 张里 5 张是蓝色），下身 **深色长裤**，脚穿深色布鞋 / 胶鞋；衣服款式老旧、宽松。
- **活动范围**：几乎只出现在 **双溪村老家院子**——水泥晒坝、贴白瓷砖的民房与拱形门洞前、散养鸡群附近。
- **典型行为**：扛运金黄色玉米 / 稻谷作物捆、手持长棍或细竹竿、提棕色竹篮、用小碗或瓢撒饲料喂鸡、双手背在身后慢悠悠踱步。

### ❌ 易变特征（不能作为身份依据，变了不算矛盾）

- **上衣颜色**：蓝色、黑色都会穿。
- **裤子颜色**：黑色、灰色都会穿。
- **是否戴草帽**：干农活（扛作物）时戴宽檐草帽，日常喂鸡溜达时不戴。
- **手持物品**：每次都不同（作物捆 / 长棍 / 竹篮 / 黄碗 / 小铲子）。

> 结论：**身份锚点是「瘦削高龄老人 + 灰白短发 + 老式蓝衣深裤 + 老家院子里的农家日常活动」这组复合特征**，单独任何一项都不足以定身份。

### 🚫 未采集到的特征（诚实说明）

7 张样本里**没有一张清晰的正面大头照**：面部不是被宽檐草帽遮住，就是侧身、背身或远景。因此**无法提炼可靠的面部特征**（眉、眼、鼻、嘴的具体形态），提示词里也不应编造。当前方案是“**靠体型 + 发型 + 着装风格 + 场景行为认人**”，不是“靠脸认人”。

## 三、先把能力边界说清楚

纯文本提示词让视觉模型认人，**能做，但有天花板**，必须提前知道：

1. **视觉模型不会“记住”一个没见过的陌生人。** 它只能按文字描述去画面里逐条匹配特征。所以提示词写得越像“规则”（满足什么、排除什么），越稳；写得越像“抒情”（慈祥的老人），越不靠谱。
2. **衣服 / 帽子是可变特征，以它们为主依据必然翻车。** 爷爷换件黑衣、摘了草帽，纯靠“蓝衣草帽”写的提示词就会漏认；反过来，同村另一位蓝衣老人可能被误认。这就是上面把特征分成“稳定 / 易变”的原因。
3. **本项目对“幻觉”有过血泪教训**（见 README：旧 prompt 里“请仔细检查远处的人形轮廓”逼模型编出“一个人影在走，旁边还有只狗”）。所以提示词必须显式压制猜测：**拿不准就判“无法确认”，禁止“似乎 / 可能 / 好像”**。
4. **真要高可靠，得靠参考图（few-shot）**，把爷爷照片和监控图一起喂给模型比对——这是第八节的升级方向。纯文本提示词是“够用、省改造成本”的方案。

## 四、推荐提示词（完整版）

可直接替换 `config.json → ai.prompt`。**输出格式严格沿用现有约定**：第一行仍只输出【有人】/【无人】，保证 `lib/judge.js` 的判人门控（marker / 首行裸结论）完全不受影响；爷爷判定放在第二行，`judge.js` 不会误解析（它只认“有人 / 无人”两种标记）。

```
这是湖南常德双溪村老家院子的监控抓拍画面。请完成两件事。

第一步：判断画面中是否有人。第一行必须且只能输出【有人】或【无人】。

第二步：如果有人，进一步判断这个人是不是「爷爷」——家里一位高龄老人。另起一行输出【是爷爷】【不是爷爷】或【无法确认】，然后用一两句话说明依据。最后用一句话简述画面内容，如有异常请明确指出（无异常则写“无异常”）。

【爷爷的稳定特征】（多张抓拍中反复出现，可作身份依据）：
- 高龄老年男性（看起来约80岁上下），身材偏瘦削、精干，不臃肿
- 灰白色短寸头
- 穿着朴素的老式农家服装：多为蓝色系长袖上衣/外套，深色长裤，深色布鞋/胶鞋，款式老旧宽松
- 出现位置几乎都是老家院子：水泥晒坝、贴白瓷砖的民房与拱形门洞前、散养鸡群附近
- 常见动作：扛运金黄色玉米/稻谷作物捆、手持长棍或细竹竿、提棕色竹篮、用小碗或瓢撒饲料喂鸡、双手背在身后慢悠悠踱步

【不能单凭的可变特征】（变了不算矛盾，不要因为它们就否定）：
- 上衣颜色：蓝色、黑色都会穿
- 裤子颜色：黑色、灰色都会穿
- 是否戴草帽：干农活时戴宽檐草帽，日常喂鸡溜达时不戴
- 手里拿的东西：每次都不同

【判断规则】务必遵守：
1. 只有同时满足「瘦削高龄老人 + 灰白短发 + 老式农家着装 + 在老家院子做农家日常活动」，才判【是爷爷】。
2. 画面里的人若明显年轻、体态明显不同（如高大壮实、弯腰驼背明显）、穿着现代（西装、鲜艳运动服）、或出现在明显非老家院子的场景，判【不是爷爷】。
3. 人物太小、面部被遮、逆光、模糊到看不清体态发型时，判【无法确认】，不要猜。
4. 严禁用“似乎/可能/好像/大概”充当依据；拿不准一律降级为【无法确认】。
5. 只有一两个远处人影晃动、分不清任何特征时：【有人】照常判，爷爷判定给【无法确认】。
6. 鸡、狗、家禽、树影、光斑、晾晒的衣物、农具雕塑都不是人，不要判成有人。
```

**输出示例（给模型对齐格式用）：**

```
【有人】
【是爷爷】
灰白短发的瘦削老人穿蓝色长袖上衣，在水泥晒坝上撒饲料喂鸡，与爷爷的稳定特征一致。无异常
```

```
【有人】
【无法确认】
画面远端有一个人影沿小路走过，但距离太远看不清体态和发型，无法判断是否为爷爷。无异常
```

```
【无人】
画面是空无一人的院子晒坝，几只鸡在啄食。无异常
```

## 六、怎么接进项目（只改一处）

三个服务的提示词**都读同一个字段** `config.json → ai.prompt`：

| 服务 | 提示词来源 |
|---|---|
| `monitor.js`（常驻监控） | `lib/ai.js` → `aiCfg.prompt` |
| `webapp.js`（Web 看板手动分析） | `lib/ai.js` → `aiCfg.prompt` |
| `webhook.js`（微信服务自动判读） | 第 579 行 `A.prompt`，即 `cfg.ai.prompt` |

所以**只改 `config.json → ai.prompt` 一处，三个服务全部生效**，无需动代码。改完用 `node monitor.js once` 手动跑一张图验证全链路。

> 注意 `config.json` 含全部密钥且被 `.gitignore` 排除，改它不会进 Git；但它是**正在运行的生产配置**，建议先备份再改，或先在 `config.example.json` 里留档。

## 八、更可靠的升级方向：参考图比对（few-shot）

纯文本描述的表达能力有上限。**真正稳的做法是把爷爷的照片和监控图一起喂给模型**：“图 1 是爷爷，判断图 2 里有没有图 1 这个人。” 素材都现成（`person/` 目录），只需让 `lib/ai.js` 支持发多张图：

```js
// lib/ai.js — analyzeImage 增加参考图支持（草案）
async function analyzeImage(aiCfg, imageFile, promptOverride, refImages) {
  // ... 前面不变 ...
  const content = [];
  if (refImages && refImages.length) {
    content.push({ type: "text", text: "图中这位老人是「爷爷」（多张不同穿着角度的参考照）：" });
    for (const ref of refImages) {
      const rb = (await aiInputImage(ref)).toString("base64");
      content.push({ type: "image_url", image_url: { url: "data:image/jpeg;base64," + rb } });
    }
    content.push({ type: "text", text: "下面是监控抓拍画面，请判断里面有没有上面这位爷爷：" });
  }
  content.push({ type: "image_url", image_url: { url: "data:image/jpeg;base64," + b64 } });
  content.push({ type: "text", text: promptOverride || aiCfg.prompt });
  const bodyBase = { messages: [{ role: "user", content: content }], max_tokens: aiCfg.maxTokens || 300 };
  // ...
}
```

配合在 `config.json → ai` 下加一个配置项指向参考图目录：

```json
"ai": {
  "personRefs": "person",
  "prompt": "（第四节完整版 prompt，措辞改为「和参考照里的是不是同一个人」）"
}
```

**代价与注意**：
- 参考图会显著增加单次请求的体积和耗时（多张 base64 图），建议参考图预先压到 512 宽、只放 2~3 张代表性的（如一张正面、一张戴草帽干活的）。
- 支持多图的视觉模型才可用（glm-4v 系列、agnes-2.5 等主流视觉模型支持；个别只收单图的渠道需要过滤）。
- 改造涉及 `lib/ai.js`（monitor / webapp）和 `webhook.js` 里独立实现的那套 `analyzeImageAI`，两处都要带上参考图，逻辑才一致。

## 九、一句话总结

- **能立刻做**：把第四节完整版提示词贴进 `config.json → ai.prompt`，一处改动、三个服务全生效，零代码改动、可随时回滚。
- **它的真实水平**：靠“瘦削高龄 + 灰白短发 + 老式蓝衣深裤 + 院子里的农家日常”这组复合特征认人，**不是靠脸**；换衣服 / 戴摘草帽不受影响，但人物太小、逆光、遮挡时会主动报“无法确认”而不是瞎猜——这是设计上的保守取舍，宁可漏报也不误报成“是爷爷”。
- **想再上一层**：走第八节的参考图比对（few-shot），把 `person/` 里那几张照片真正用起来，准确率会有质的提升，代价是改 `lib/ai.js` + `webhook.js` 两处调用。
