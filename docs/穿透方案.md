# 内网穿透方案选型（踩坑记录）

微信回调必须有一个**公网可访问**的地址。前后试过三种方案，结论：**用花生壳**。

> 文档中的域名一律用占位符表示，真实域名填在 `config.json` 的 `wxTest.publicBase`（该文件不上传 Git）。

---

## 一、三种方案对比

| 方案 | 域名是否固定 | 国内可达性 | 结论 |
|------|------------|-----------|------|
| **花生壳(oray) 免费版** | ✅ 固定 `xxx.vicp.fun` | ✅ 国内节点，微信服务器可达 | ✅ **当前方案** |
| Tailscale Funnel | ✅ 固定 `xxx.ts.net` | ❌ 公网流量必经 Cloudflare 边缘，国内不可达 | ⚠️ 仅作远程运维用，不做微信回调 |
| Cloudflare Tunnel | ❌ 免费版每次重启都换新随机域名 | ⚠️ 不稳，且国内访问不佳 | ❌ 已弃用 |

### 为什么放弃 Tailscale Funnel

Funnel 的公网流量**必须经过 Cloudflare 边缘节点**，而中国大陆没有节点，最近的要走东京 DERP（约 100ms），国际链路一抖微信回调就超时 → 公众号报「服务出现故障」。

Tailscale 本体仍然保留并常驻：它用来从外网访问家里那台跑本地模型的机器，**IPv6 直连 43ms 很稳**，和 Funnel 是两回事。

### 为什么放弃 Cloudflare Tunnel

免费版（quick tunnel）每次启动生成随机域名，一重启就要去公众号后台改 URL，运维成本不可接受。命名隧道要绑信用卡/域名，没必要。

## 二、花生壳配置（当前方案）

1. 安装花生壳客户端，登录，**设置开机自启**（关键：客户端必须常驻）
2. 添加映射：
   - 应用类型：**HTTP**
   - 外网域名：分配的固定域名（形如 `xxxxx.vicp.fun`）
   - 外网端口：80
   - 内网主机：`127.0.0.1`
   - 内网端口：`8787`
3. 把域名填进 `config.json` → `wxTest.publicBase`，并把 `tunnelType` 设为 `oray`
4. 公众号后台的接口配置 URL 也填这个域名

免费版限制：带宽 1Mbps、每月 1GB 流量（次月自动重置）。对于「微信指令回调 + 偶尔一张抓图」完全够用。

## 三、排查经验（重要）

### 现象：`curl` 花生壳返回 **503**，但手机微信明明能用

**原因**：本机开着 Clash 之类的代理（`127.0.0.1:10808`），curl 走了代理出口，花生壳免费版把该出口 IP 判定为数据中心/爬虫而限流。

**判断方法**：绕开代理再测：

```bash
curl --noproxy '*' http://你的域名.vicp.fun/health
```

**结论**：走代理的 503 是**测量误差**，不是真实故障。排查时务必用 `--noproxy '*'`。

### 现象：花生壳直连返回 **Empty reply from server (52)**

隧道确实断了。检查清单：

1. 花生壳客户端是否在运行（核心穿透进程是 `PHTunnel.exe`，不是 `orayfilesvr.exe`）
2. 客户端是否登录、映射是否还在
3. 本机 webhook 服务是否健康：`curl http://127.0.0.1:8787/health`

三层同时确认：本地服务 OK + 公网域名 OK，才能确定链路通。

### 现象：微信点菜单「服务出现故障」

按上面顺序排查。**绝大多数是花生壳客户端掉线**，而不是代码问题。判断依据：本地 `127.0.0.1:8787/health` 正常、但公网域名不通，就是穿透层的问题。

## 四、一键启动脚本做了什么

`一键启动全部.bat` 的第 1 步就是隧道：

- 读 `config.json` 的 `wxTest.publicBase` 作为隧道 URL
- 若配置了 `cfTunnel.name` 则走 Cloudflare 命名隧道（历史遗留分支，一般走不到）
- 否则默认尝试 `tailscale funnel --bg 8787`
- 最后把实际 URL 写回 `config.json` 的 `wxTest.publicBase`

> 注意：脚本里的 Tailscale 分支是历史遗留。**实际上微信回调请始终依赖花生壳客户端常驻**，不要依赖脚本拉起 Funnel。
