## 2026-09-11 ～ 09-13（代码审查 + 优化批次）

### 新增公共模块（lib/）
- `lib/judge.js`：判人/异常结论的**唯一实现**，三个服务共用。三级判定（显式标记【有人】/【无人】 → 首行裸结论 → 逐句否定优先），修复旧正则缺 `m` 标志、「没有人」被误判「有人」等真实缺陷；结论解析失败时报警链路不拦截推送并打 `⚠ AI结论无法解析` 警告。
- `lib/store.js`：`data/*.json` 跨进程**文件锁 + 读-改-写事务**。此前 webhook/webapp/monitor 三进程「读全量→改→写全量」互相丢事件（压测 600+ 条），现在统一走 `store.updateEvents()`，锁内重读最新内容，返回值 `{ok, written}` 需处理。

### webhook.js（微信/萤石服务，本次改动最大）
- 新增**文本指令查历史**（如「查询双溪村10点左右的监控」）：时间解析（±1小时/时段词/昨天前天）→ 文字汇总 + 最多3张截图 + 图文卡片进 `/history` 完整页；查询前向萤石云端按时间窗补录（云端仅存近 7 天）。
- 新增**历史记录菜单/页面**：公众号菜单「历史记录」按钮（key=history）、`/history` 页（日期导航 + 有人/全部/日报三标签、分组成员只看本村）。
- **设备端人形标签与 AI 判定区分**：设备端(15504/human标签)结论无条件采信但标记 `provider` 为空；看板措辞区分「有人」(红·AI判定) 与「人形·设备端」(黄)。
- **同活动补图**：萤石对一次活动连推多帧，人形标签那条缺截图时在事务锁内用后续那条的截图补齐，不再产生无图记录。
- **抓图分目录**：普通移动侦测的临时图单独落 `captures/motion/`（默认保留 3 小时，仅供垫图），主目录只留事件图（默认 60 天）——实测孤儿图曾占 96%。

### webapp.js / webapp.html（看板）
- 配合「人形·设备端」黄色措辞；无配图记录渲染「无截图」占位，图片被清理显示「截图已失效」，不再黑屏。
- 历史查询/日报数据接口与页面适配。

### monitor.js（常驻监控）
- 判人解析改用 `lib/judge.js`；事件写入改用 `lib/store.js` 事务。

### AI prompt 加固
- `config.json → ai.prompt` 明确：须分辨**头部与躯干**才算人；阴影/树影/反光/挂衣/塑料袋/宠物一律不算；禁止用「似乎/可能」作判「有人」理由。旧 prompt「仔细检查远处人形轮廓」曾让 glm-4v-flash 对纯树影画面编造出「人影+狗」。

### 新增运维工具（tools/，共 7 个）
- `update_menu.js`：追加公众号「历史记录」菜单（幂等）；配套 `更新公众号菜单.bat`。
- `rejudge_events.js`：用最新判人逻辑校正存量记录（预演 / --apply，自动备份）。
- `recheck_events.js`：设备端直通无 AI 结论的存量记录复核。
- `repair_noimage_events.js`：无图记录按「同设备+时间邻近」找回孤儿截图。
- `sweep_captures.js`：清理历史孤儿抓图。
- `stress_events.js`(+worker)：多进程并发写回归测试（无锁对照组丢 600+ 条）。
