## 2026-09-29（续4）：车辆事件改为「算法预筛 + 同图 AI 确认」制

### 背景
- 用户实测反馈：收到的车辆推送大量是"标题检测到有车、AI结论却说没车"。数据核实：117 条本地车辆命中事件的配图比报警时刻平均晚 11.5 秒（61 条晚于 10 秒，车已离开），38% 的车辆事件 AI 明确说没车——与"图里有人判无人"同根因（旧逻辑高清截帧优先）。
- 用生产同款链路（lib/ai.js + 车辆复核prompt）实测当前 mota 模型 DeepSeek-V4.1-Flash：4 张图 4/4 准确（含"人骑电动车"最难形态，正确答出"红黑配色电动踏板车"；两张空院子未幻觉）。"AI 认不出乡村车辆"的旧前提已不成立。

### webhook.js
- **车辆事件改 AI 确认制**：本地帧差算法只做免费预筛，命中后**用同一张图**跑车辆复核 AI；`vehVerdictFromAi` 明确说"no"才拦截（仅记录看板），未表态/渠道全失败仍放行（不确定不拦防漏报）。标题从此不再出现"检测到有车但AI说没车"的自相矛盾。回退开关：`config.json → vehicleDetect.aiConfirm = false` 恢复旧 B 方案。
- **同图保证**：本地算法命中的是 motion/ 里的报警快照——主链路现在直接把这张快照搬进 captures/ 作为事件配图（内容与时机都和算法看到的一致），不再重新下载/抓帧。字面意义的"算法看的图 = AI 分析的图 = 给用户看的图"。
- **修 `vehVerdictFromAi`**（原为死代码，此次启用）：① 否定词表补"未看到/未发现/无"——旧版会把车辆 prompt 的否定回答"画面中未看到车辆"整篇扫描误判成 yes；② 按 prompt 约定以**最后一句**为结论（前文枚举可能同时出现"没有看到人"和"发现摩托车"）；③ 新增肯定判定"量词/姿态 + 具体车型"（"有一辆黑色摩托车/骑着电动车"），优先于同句并存的补充否定（"……未发现**其他**行驶中的车辆"），负向环视排除"没有一辆"。
- VERSION → 2026-09-29.43。

### 验证
- 合成用例 10/10（含实测踩坑的肯定+补充否定并存句）。
- 4 张实图端到端（mota + 生产 prompt + 新门控）：2 张确认有车 → 推送；2 张空院子 → 拦截仅记录。全对。

## 2026-09-29（续3）：全链路时序审查（触发→抓图→AI→推送→记录→展示）

按真实流程逐条链路走查（替代逐函数审读），新发现并修复 3 处：

### webhook.js
- **同设备主链路串行化**：原来同设备的推送消息**并发**处理——下一条消息在上一条的 AI 尚未回写时到达（person 仍是 false），带截图的消息会走"二次判定"分支再建一条同活动事件（看板重复卡片），且 300 秒推送去重读到的 `pushed` 还是 false → **同活动推送两条**（2026-09-14"一次活动推两条"事故的残余形态：间隔大于 90 秒小于 AI 延迟+推送耗时窗口时仍可复现）。现按设备序列号入队严格串行（`enqueueForSerial`），不同设备仍并行。沙箱验证 4 场景：同设备严格串行 / 异设备并行 / 出错不断链 / 队列可复用。
- **隧道未开时推送/日报不再发相对路径链接**：原来 `detailUrl = tokUrl(pubBase + "/detail?...")` 在 `pubBase` 为空（花生壳未运行）时构造出 `/detail?file=..` 相对路径塞进模板消息，微信里点击无反应、文案却说"点击查看现场照片 👉"；日报 `todayUrl` 同病。现 pubBase 为空时不给 url，文案如实说明"内网穿透未开启，请到电脑看板查看"。
- **报警截图文件名防冲突**：同一活动多条消息携带相同报警时间时会生成同名 `_p{ts}.jpg`，两条事件共用一个 file 会让 `analyzeAndStore` 只回写先匹配到的那条（另一条的 ai 永远是占位）。已存在同名文件时自动加时间后缀。

## 2026-09-29（续2）：「图里有人、结论无人」——AI 分析图与展示图不一致根治

### 事故还原（2026-09-29 16:11 骑车人事件）
- 16:11:37 设备人形检测(SmartHumanDet)消息**自带有人骑车的快照**（已取回验证：`data/验证_161137人形快照.jpg`，画面清晰）；
- 该消息因"旧事件判过无人 + 自带截图"触发二次判定放行（机制正常），但选图逻辑**高清截帧优先**——16:11:50 才抓到帧，人 12 秒前已骑走，AI 对空帧判「无人」（对它看到的图判断正确）；
- 自带的有人快照从未被分析；看板按"就近抓图"给卡片配了 16:11:38 的有人游离图 + 无人文案 → 用户看到"明明有人判无人"。

### webhook.js（主链路选图）
- **报警自带截图(picUrl)改为第一优先**，captureHD 只在无截图/下载失败/截图为占位图时启用：判人看的是"报警时刻"，时机远比分辨率重要（768x432 足够 AI 判读），同时每条带截图消息省一次拉流。截图下载加 ≤640 宽占位图校验。
- VERSION → 2026-09-29.41。

### webapp.js（推送记录页图文同源）
- `buildPushGroups` 关联逻辑反转：先按「同设备±90秒(有AI结论优先, 同分取时间最近)」定事件，**配图直接用事件自己的 file**（AI 分析的就是这张）；时间窗未命中才按图反查兜底；事件无图时用就近抓图（此时事件本就无AI结论，不存在错位）。新逻辑用 16:11 事故数据回放验证：卡片配图从"16:11:38 有人图配无人文案"变为"16:11:50 空帧配无人文案"，图文一致。
- VERSION → 2026-09-29.28。

### 效果
- 今后同类事件：人形消息自带的报警时刻快照会被直接分析 → 判有人 → 正常推送；
- 看板任何卡片的文案与配图必然来自同一张图，"分析图≠展示图"从结构上不再可能。
